# Token 用量助手 1.6.0：阶段 3，DeepSeek 官方按量账户

本版完成阶段 3 的开发与样例验收：DeepSeek 官方 API Key 连接、账户余额看板、悬浮窗、异常与缓存状态。保留 1.5.1 的 Codex 自动发现、Claude 本机组件，以及原平台和四种工具来源。阶段 4 的账户关联 / 核对、阶段 5 macOS、阶段 6 第三方中转尚未实施。

## 从哪里添加

1. 打开 **账户与设置 → 平台 → DeepSeek · 官方按量**。
2. 在应用内填写官方 API Key，可添加账户备注，点击“验证并添加账户”。密钥由 Windows 加密存储，主面板与工具分析状态中不返回密钥。
3. 在 **用量总览** 查看总可用余额、赠金余额、充值余额和币种；悬浮窗显示各币种余额，展开后显示赠金 / 充值明细。
4. 点击“查看工具分析”查看已经接入的本机用量；也可在“用量分析 → 工具分析”选择 Zcode、Harness、Codex 或 Claude Code 数据源。

只支持官方固定 `https://api.deepseek.com/user/balance`，Bearer 鉴权、HTTPS 只读 GET，禁止重定向。不提供自定义 API 地址，不调用模型、不充值、不读取其他应用的 Key。

## 余额与费用的口径

| 项目 | 本版行为 |
|---|---|
| 账户是否有余额可用于调用 | 展示官方 `is_available`，与查询连接状态分开 |
| 总可用余额 | 展示 `total_balance`，包含赠金和充值余额，三项不重复相加 |
| 赠金 | `granted_balance`，官方定义为未过期赠金 |
| 充值余额 | `topped_up_balance` |
| 币种 | CNY 与 USD 分别显示，不换汇、不相加 |
| 精度 | 金额以十进制字符串保存和显示，不通过浮点计算舍入小额或大额 |
| 零余额 | 有效响应中的零是查询成功；密钥错误、断网等查询失败不会伪造为零 |
| 字段缺失 | 保持未知，显示“—”；空币种列表单独提示；无法识别的格式保留之前成功数据并报错 |
| 充值 / 赠金变动 | 更新余额快照，不从余额差推算消费、扣费来源或账单 |
| 工具 Token 与费用 | 使用独立的本机工具记录和用户配置的模型单价估算，保留原币种；不是官方账单 |

本次没有完整历史账单或官方 Token 汇总。没有套餐总额度，故不显示 5h / 周 / 月百分比、余额耗尽预测或百分比低余额提醒。原有套餐提醒保持原逻辑。

连接成功只要求接口具备的余额数据，不再要求套餐额度或 Token 汇总。错误时保留带成功时间的旧余额；401 / 403 暂停自动查询，429 遵守 Retry-After，其他连接异常降低重试频率。HTTP 402 也仅显示官方余额不足错误，不擅自生成零余额。

同一个 Key 再次添加会更新原连接；不同 Key 可独立保存，但可能共享同一计费账户，本版不会把这些余额汇总。工具记录不因切换账户而改变归属。多 Key 人工归组、账户关联、覆盖核对按阶段 4 单独实施。

## 验证与限制

桌面回归 **186 项通过，0 失败、0 跳过**，Sites 兼容 **4 项通过**。其中 21 项新增余额测试覆盖官方样例、精度、多币种、未知字段、零余额、鉴权 / 权限、402、429、断网、超时、响应变化、充值赠金变化、加密持久化及原账户保留。

最终发布包检查、原生余额界面、Windows 加密重载、1.5.1 → 1.6.0 的 23 项原生模块升级检查与载荷哈希见源码中的 `docs/verification-1.6.0`。样例原生测试包含主面板、深浅色、悬浮窗展开 / 收起、零余额与失败状态、工具分析入口。测试只使用隔离样例账户，不调用真实模型。

**尚未使用真实 DeepSeek Key 进行账户实测**，需用户在应用内配置后核对；请勿在聊天或源码中提供密钥。Claude 与首批新增 Coding Plan 真实核账仍保留原缺口。按用户要求未做新的长时间稳定性测试。升级检查是隔离的原生模块检查，不是实际 NSIS 覆盖安装；真实覆盖安装、重启启动、休眠恢复仍待专门验收。原生自检使用 `--disable-gpu`，正常启动不强制该参数。开发交付尚未签名。

退出旧版后可运行新的免安装程序或安装版。使用原 userData、加密凭据及偏好存储；无需主动重建已有连接。添加新平台账户后回退旧版本可能因旧版不认识新平台而无法加载账户列表，回退前应保留升级前的加密数据备份；本次检查仅验证添加新平台前旧数据可读。
