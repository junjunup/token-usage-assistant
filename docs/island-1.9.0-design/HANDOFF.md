## 1. 背景与起点

用户问：Mac 上悬浮窗能否放到刘海屏位置，做灵动岛式设计。调研后结论：**可以做，Electron 44.4.4（项目锁定版本）的现有 API 足够**，但有硬约束，且必须在用户真机上验收，不得在无真机验证时宣称已验证。

### 已核实的技术事实

- 现有悬浮窗用 `setAlwaysOnTop(true,'floating')`（`desktop/main.cjs:49`），该层级在菜单栏**之下**；岛需要升到 `status`（25）或 `pop-up-menu`（101）。`setVisibleOnAllWorkspaces(true,{visibleOnFullScreen:true})` 已在用。
- Electron 的 `Display` 结构**没有**刘海 / `safeAreaInsets` 字段（electron#31478 未实现）。判断是否刘海屏：`workArea.y − bounds.y`（无刘海菜单栏约 24pt，有刘海约 37–39pt，>~30 判定为刘海屏）。**刘海精确宽度拿不到**。
- 刘海是**物理开孔，摄像头位置没有像素，任何内容都画不进去**。收纳/悬停态信息只能绘制在刘海两侧的「耳朵」屏区。
- `setContentProtection(true)` 可防截屏/录屏/共享（boring.notch 把它当卖点），但文档明确：使用 ScreenCaptureKit 的新版应用可能仍能捕获，不得承诺 100%。
- `setIgnoreMouseEvents(true,{forward:true})` 让岛区域外鼠标穿透；动画后调 `invalidateShadow()` 消除透明窗口残影。
- 全屏应用会把刘海区画进内容，岛应默认全屏自动隐藏（检测：监听 `display-metrics-changed`，比较内建屏 `workArea` 与 `bounds`）。
- 岛体必须近黑色（与刘海硬件融合），不随明暗主题变化——这是物理约束，不是视觉重设计。

| NotchNest | $14.99 买断 | 10 组件（含 AI 剪贴板、番茄钟）；无刘海 Mac 渲染为顶部下拉面板 |

**定位分野**：Vibe Island = 「遥控器」（审批/跳转，违反我们的只读监控红线）；我们 = 「仪表盘 + 账本」（配额、余额、Token 经济、本地分析）。**不走** Vibe Island 读本地 Claude 登录信息的路线（凭据红线）。

**明确不做**：终端跳转 / 权限审批、媒体控制 / HUD / 歌词、文件架 / AirDrop、剪贴板历史、摄像头 Mirror、游戏。

**从竞品差评提炼的红线**：外接屏回退经典悬浮窗（不画假刘海）；全屏自动隐藏；稳定性是口碑分水岭（岛走 beta + 真机验收清单）；真机验收时给出实测 RAM/CPU 数字。

## 3. 定稿设计（已定）

### 3.1 交互：B 耳区收纳 + A 面板悬停直落（融合方案 v2）

- **收纳态**：纯黑胶囊跨过刘海，**内容只画在两侧耳区**（中心偏移 108px 起 = 100px 保守刘海半宽 + 16px 缓冲）；收纳宽度 360px，两耳各约 80px，常显迷你分段条 + 数值（82% 亮度）。摄像头区纯黑让位，刘海元素绘制在最上层。
- **悬停态**：耳区停留 ≥150ms 后，面板（470px 单栏：双配额 + Token/费用/余额三格 + 账户 chip 行 + 「主窗口 ›」）直接落下；移出 200ms 宽限后收回；220ms spring 下落。**零点击，移除点击展开与中间提亮态**。
- **点击语义**：点岛体 = 打开主窗口配额页；面板行项跳转主窗口对应视图；**无固定展开**（常驻大窗交给经典悬浮窗）。
- **右耳优先**：左耳紧邻应用菜单会被挤，右耳（刘海与时钟之间）宽度稳定，菜单栏拥挤时优先保证右耳。
- **不进岛**：B 的双栏全景、C 的多账户页签，均留在主窗口。

### 3.2 数据：槽位制四型（耳区与面板块由账户数据形态决定，不写死「5H/周」）

| 槽型 | 判定（真实字段，已核对 `desktop/domain.cjs` / `balance-domain.cjs`） | 耳区 | 面板 |
|---|---|---|---|
| 窗口配额 | `remainingPercent` 有值且 `resetState='scheduled'` | 标签 + 迷你分段条 + % | 分段条 + 重置时间 |
| 余额（纯 API） | `balances[]` + `isAvailable` | 等宽数字 + 原始币种，**永不画条**（无分母） | 大号余额行 + is_available + 「无重置窗口」 |
| 不限量 / 未启用 | `unlimited` / `resetState='idle'`（resetAt=0） | 「不限」/ 留空 | 「不限」/「窗口显式未启用」 |
| 不可用 | 企业版 / 未验证契约 | 「—」 | 「—」行，不占告警位 |

- **耳位优先级**：告警中（红 > 琥珀）> 窗口剩余最少 > 余额低于阈值 > 默认账户；多账户同时告警叠加数字徽标；空耳位保持纯黑，不编造内容。
- **诚实红线**：resetAt=0 显示「未启用」，绝不发明 5h 倒计时；缺 reset 数据 = 「—」；余额不画百分比条；不从余额差推算消耗；余额预估仅基于已确认关联的工具用量且样本充足；订阅百分比永不套用于 API 余额。
- **告警**：窗口沿用现有 <20% 琥珀 / <10% 红；余额阈值用户自设；缺数据不告警。

### 3.3 设置页：四层模型

1. **自动默认**（零配置可用）：首次启用识别账户类型自动填充——左耳 = 最紧急窗口槽（有 5h 用 5h）；右耳 = 周配额或首个余额账户；纯 API 双账户各占一耳；单账户只占左耳、右耳留黑。
2. **显式绑定**：左右耳各一个**自定义下拉（非原生）**，选项只列实际存在的槽，分组「窗口配额 / 余额 / 其他」，如实标注「未启用」「需启用」；绑定未启用槽时耳区回退默认并在设置标记。
3. **告警临时接管耳区**（默认开）：告警时临时占用耳位、解除后恢复绑定。
4. **失效回退**：账户删除 / 契约失效 → 回退默认规则并如实标记，绝不渲染编造内容。

设置组完整项：悬浮窗形态（经典 / 灵动岛，**默认经典**）· 左耳内容 · 右耳内容 · 告警临时接管 · 消耗瞬态提示 · 刘海宽度微调（内置机型预设表 + 手动微调，真机校准一次）· 截屏与共享保护（默认开）· 步进刷新频率（2s / 5s / 10s，默认 5s）。

### 3.4 整合功能落位与交付阶段

| 功能 | 岛内落位 | 阶段 |
|---|---|---|
| 截屏 / 共享保护 | 设置 toggle（`setContentProtection`），文档如实标注 ScreenCaptureKit 例外 | **首版** |
| 微动效 | 重置完成：分段条回满绿 + 800ms 单次柔光，不循环 | **首版** |
| 快捷入口 | 面板 footer「官方用量页 ›」，仅打开官方页面链接，不代登录不抓取 | **首版** |
| 正在运行 · 实时会话 | 耳位可绑定槽（脉冲点 + 步进增量 + 「8s 前」）+ 面板会话行；三态：运行 / 空闲 / 「—」 | 增量一 |
| 重置倒计时 | 窗口槽倒计时变体；临期（<15min）临时切换 | 增量一 |
| **消耗瞬态提示** | 左耳 crossfade「会话 +3.2k」（Token 紫）3–4s，**宽度不变**；合并冷却 ≥120s 或累计 ≥5%；跨阈值 / 告警走接管通道；悬停时推迟；多账户取最大差值带短标；默认开 | 增量一 |
| 本地事件流 | 面板「最近事件」块（与告警同色系）；全量在主窗口 | 增量二 |
| 组件健康 | 面板 chip 圆点扩展为 CLI / 采集器 / SQLite 状态语义 | 增量二 |

- **首版（岛 v1）**：全部是呈现层，不依赖新数据管线——槽位岛 + 设置四层 + 截屏保护 + 微动效 + 快捷入口。
- **增量一**：reader 加 latest-since-cursor 投影 + monitor 会话聚合 →「正在运行」、倒计时槽、消耗瞬态、步进刷新生效。
- **增量二**：本地事件存储 + 组件状态聚合。
- **优先级定型**：告警接管（琥珀/红）> 临期倒计时切换 > 消耗瞬态 > 用户绑定内容。

### 3.5 「实时增量」的可行性结论（「正在运行」与消耗瞬态的数据基础）

- **能做，但是步进准实时，不是逐 token 流式**：Zcode / OpenCode 在每个 step 落盘后 ≤5s 可见（默认 5s 轮询）。
- 代码已核实：`zcode-reader.cjs` 按 `model_usage.started_at` 逐行读取；`opencode-reader.cjs` 按 `step-finish` part 的 `at` 投影；`monitor.cjs` 是 `schedule(delay)` 轮询 + broadcast——增量 = 游标之后的新行求和，是纯增量改动。
- **分层承诺**：Zcode / OpenCode 步进增量；**Codex 会话增量显示「—」**（rollout metadata 非请求数，既定结论），用官方 5h/周百分比下降作活跃信号；Claude 首版不显示实时。
- **规则**：「运行中」= 最近 step 记录在 ~90s 内、来自会话本体（排除 legacy mirror / fork 继承）；不用进程存在推断，不推断账户归属（accountId null 不变）；cache/reasoning 不重复计；失败/取消的 reported usage 仍计入；UI 三态不显示 0。
- **消耗瞬态措辞**：本地 turn 增量优先；轮询差值（如 Codex）只显示「余量 −0.8%」，**不做「本轮」归因**（平台轮询有滞后且聚合不透明）。
- 2s 高频轮询的 CPU/内存在真机验收时给实测数，不凭推断宣称。

## 6. 实施约束（来自项目 AGENTS.md，实现阶段必须遵守）

- **每次代码变更后必须构建并更新 Windows 安装包 + 便携版**，验证包内版本与源码一致，保留旧发布产物；不得把仅源码变更报告为已交付。
- **Windows 行为零改动**；appId / executableName / userData 路径不变；不引入新原生依赖（对未签名 Mac trial 友好）。
- 经典悬浮窗保持默认形态，岛是设置中的显式选项，升级不改现有用户偏好与窗口位置。
- 外接屏与 Windows 回退经典悬浮窗；仅内建刘海屏启用岛。
- Mac 当前交付形态：本机 electron-builder 构建的真实 `.app` + DMG/ZIP（arm64、ad-hoc 签名、无公证）；真机验收（Keychain / 实际工具 / 菜单栏与窗口行为 / 睡眠 / 安装升级）仍待用户 Mac 完成。
- 建议实现路线：先做最小 POC（只验证 窗口层级 / 耳区定位 / 全屏隐藏 / 鼠标穿透 四点），用户真机确认手感后再作为正式版本交付，并附文档页 + 真机验收清单；POC 阶段不宣称真机已验证。
- 数据红线：缺失显示「—」非 0；工具记录 accountId null；不读取任何对话内容/凭据；Codex 查询只读；不做长时间稳定性测试。
- 版本号：当前 1.8.0-beta.5；岛特性按 1.9.0 线规划（版本号由用户确认）。
