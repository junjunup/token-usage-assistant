## 0. 方向调整（2026-10-18，用户决定）

用户看完 T7.1 的 POC 报告后决定：

- **放弃耳区方案**：耳区会遮挡状态栏图标、拦截鼠标，全屏时还要另做检测，代价大于收益。原 ② 告警整耳替换、⑦ 收纳态耳区随之作废。

- **展开方式 A（以后可增添的特色）**：刘海悬停下落面板，不带耳区，复用 B 的面板组件，只在内建刘海屏上启用。

## 1. 技术事实

### 1.1 菜单栏图标与弹出面板（主路径；标「待 POC」的尚未实测）

- 现状：Mac 上本应用已有一个菜单栏图标（`desktop/assets/tray.png`，18pt 模板图），点击弹出原生文字菜单（`tray.setContextMenu`）；Windows 上点击打开主窗口。
- Electron 的 `Tray` 可以在运行时换图（`tray.setImage`），也可以在图标右侧显示文字（`tray.setTitle`，macOS 专有，系统字体、颜色随菜单栏自动适配）。两行小字只能自己画成图片。图片由界面里的 canvas 绘制后转成 `nativeImage`，不需要原生依赖。
- 模板图（template image）只能单色，系统自动适配浅色 / 深色菜单栏；彩色图要自己处理菜单栏明暗，且菜单栏明暗不总等于系统主题（壁纸着色等）——**待 POC**。
- 想要「左键弹面板、右键原生菜单」，就不能再调用 `setContextMenu`（设置后左键也会弹菜单），要改为 `click` 时切换面板、`right-click` 时 `popUpContextMenu`——**待 POC**。
- 面板是无边框窗口，按 `tray.getBounds()` 定位在图标正下方；失去焦点、按 Esc 或再次点击图标时收起。全屏空间里从顶部滑出菜单栏再点图标时，面板要能出现在全屏空间之上——**待 POC**。
- **菜单栏宽度是硬约束**：刘海屏 Mac 上放不下的状态栏图标会被系统直接藏到刘海后面，不给任何提示。T7.1 实测本机刘海右侧到第一个状态栏图标之间只剩约 71pt。图标越宽，越容易被藏。
- 菜单栏图标是系统绘制的一部分，屏幕共享时会被看到，`setContentProtection` 管不到它（它只对窗口生效）；弹出面板是窗口，可以开内容保护。
- **已实测（T7.7）**：Electron 44 在 macOS 15.7 上，窗口开过内容保护后，`setContentProtection(false)` 不生效（窗口仍拍不到，`isContentProtected()` 仍为 true；主窗口对照结果相同）。因此「面板截屏与共享保护」设置变化时，面板窗口会被销毁，下次打开时按新设置重建。
- 刷新只在数据变化时换图，不做循环动画。

### 1.2 刘海悬停面板（以后的特色 A；T7.1 已实测）

- `setAlwaysOnTop(true, 'status')` 的窗口层为 25，在菜单栏（24）之上；`floating`（3，现有悬浮窗）在菜单栏之下；`pop-up-menu`（101）会盖住应用的下拉菜单。
- Electron 的 `Display` 没有刘海字段；用 JXA 读 NSScreen 的 `safeAreaInsets.top`、`auxiliaryTopLeftArea`、`auxiliaryTopRightArea` 可以拿到刘海矩形（不需要原生依赖），换算方法见 `desktop/island-poc/geometry.cjs`。`workArea` 启发式在自动隐藏菜单栏时会漏判。
- 刘海是物理开孔，摄像头位置没有像素；刘海区域的窗口要近黑色，与硬件融合。
- `setIgnoreMouseEvents(true, {forward:true})` 下鼠标穿透和悬停判定正常。
- **做 A 时要解决的两个问题**：①只调用 `setVisibleOnAllWorkspaces(true)` 不能让窗口离开全屏空间，全屏切换也不触发显示器事件，需要另找检测办法或接受全屏时显示；②悬停时不能让整个窗口矩形接收点击，否则会挡住附近的状态栏图标。
- `setContentProtection(true)` 对执行模型的截屏工具有效；系统截图、录屏、会议共享待真机确认，文档要注明 ScreenCaptureKit 可能例外，不得承诺 100%。

## 3. 设计

### 3.1 交互

- **菜单栏图标（收纳态）**：一直显示在菜单栏右侧，按账户数据显示最关键的状态。**默认 ②**，设置里可切换 ① ③（用户 2026-10-18 看完 T7.1b 草图后决定）：
  - ① **只有刻度环**：用已批准的刻度环 Logo 当仪表，亮起的格数 = 剩余比例。宽度与现在相同。
  - ② **刻度环 + 一个数值**：环右侧显示一个数（例如「62%」）。
  - ③ **两行小字**：环右侧上下两行，例如 5 小时和每周两个窗口。
  - 颜色（已定）：平时单色（跟随菜单栏明暗）；告警时按程度变色，**沿用应用现有的告警规则**（2026-10-18 定）——剩余低于「提醒阈值」（设置里 10 / 20 / 30%，默认 20%）为黄色（琥珀色 token：浅色 `#ba7917`、深色 `#e3ad57`），额度用尽（`exceeded`）或月度余额 ≤0 为红色（浅色 `#dc4c57`、深色 `#ee7580`）；刻度环亮起部分和数值一起变色。
  - 刻度环画法（草图采用）：沿用 Logo 原外形，100% 时就是原 Logo；剩余越少，从上方缺口起顺时针亮起的部分越短，没亮的部分以浅色显示。缺数据、窗口未启用、余额账户时环不点亮。
- **弹出面板（展开方式 B）**：
  - 左键点击菜单栏图标，在图标正下方弹出；再点图标、点面板外、按 Esc 或切换应用时收起。
  - 右键保留现有原生菜单（有新版本时的提示、打开用量总览、显示悬浮窗、刷新用量、开机启动、退出助手等）。
  - 面板内容沿用原岛面板设计：双配额（分段条 + 重置时间）、Token / 费用 / 余额三格（Token 紫色强调）、账户 chip 行、「官方用量页 ›」「主窗口 ›」；行项点击跳转主窗口对应视图。
  - **三格只显示该账户接口返回的数据**（2026-10-18 定）：例如 Command Code 的 Token 和费用来自账户接口的用量汇总（费用由平台返回，不是估算）；接口没有的显示「—」并标注来源。本机工具统计默认不属于任何账户，不进面板。
  - **点其他账户只切换面板里查看的账户**，不改主窗口的当前账户；面板打开时默认显示菜单栏图标正在显示的那个账户（2026-10-18 定）。
  - 面板跟随应用的浅色 / 深色主题（不同于刘海悬停面板，它不需要与硬件融合）；宽 360pt（已定）。
  - 面板可键盘操作（Tab 移动、Enter 打开、Esc 收起）。
- **刘海悬停面板（展开方式 A，以后）**：鼠标在刘海停留约 150ms 后同一面板从刘海下落，移出约 200ms 后收回；近黑色；只在内建刘海屏启用，默认关闭。
- **经典悬浮窗**保持不变，仍是独立选项；三者互不替代。
- **不进面板**：多账户全景、历史图表、分析页，留在主窗口。

### 3.2 数据：槽位制四型（图标与面板由账户数据形态决定，不写死「5H/周」）

| 槽型 | 判定（真实字段，已核对 `desktop/domain.cjs` / `balance-domain.cjs`） | 菜单栏图标 | 面板 |
|---|---|---|---|
| 窗口配额 | `remainingPercent` 有值且 `resetState='scheduled'` | 刻度环按剩余比例点亮；② ③ 显示 % | 分段条 + 重置时间 |
| 余额（纯 API） | `balances[]` + `isAvailable` | **刻度环不作仪表**（没有分母）；② ③ 显示等宽数字 + 原始币种 | 大号余额行 + is_available + 「无重置窗口」 |
| 不限量 / 未启用 | `unlimited` / `resetState='idle'`（resetAt=0） | 「不限」/「未启用」；刻度环不点亮 | 「不限」/「窗口显式未启用」 |
| 不可用 | 企业版 / 未验证契约 | 「—」；刻度环灰色 | 「—」行，不占告警位 |

- **图标显示哪个账户 / 窗口**：告警中（红 > 琥珀；同级时显示最快重置的账户，④）> 窗口剩余最少 > 余额低于阈值 > 默认账户。③ 两行时同一账户的两个窗口各占一行；只有一个窗口时只显示一行。
- **诚实红线**：resetAt=0 显示「未启用」，绝不发明 5h 倒计时；缺 reset 数据 = 「—」；余额不画百分比条，也不把刻度环当余额仪表；不从余额差推算消耗；订阅百分比永不套用于 API 余额；缺数据时刻度环灰色、数值「—」，不显示 0。
- **告警**：沿用应用现有规则——剩余低于「提醒阈值」为琥珀，额度用尽或月度余额 ≤0 为红；缺数据不告警。告警时图标显示告警的那个窗口，刻度环和数值按程度变黄 / 红（见 §3.1）。
- **余额阈值（③）**：没有默认值。用户未设置阈值前**不发余额告警**；首次启用时引导用户**按币种分别设置**（USD、CNY 各自独立，不换汇、不合并）。

### 3.3 设置项

设置组完整项（界面走 D10，先出浅色和深色截图，用户确认后再实现）：

- **菜单栏图标形态**：① 只有刻度环 / ② 刻度环 + 数值 / ③ 两行小字（**默认 ②**）。
- **菜单栏图标显示用量**（默认开）：关闭后恢复静态 Logo，用于屏幕共享等场合（菜单栏图标不受内容保护覆盖）。

- **余额告警阈值**（首版之后）：按币种分别设置，未设置不告警；首版因此不发余额告警。
- **弹出面板截屏与共享保护**（默认开）：`setContentProtection`，如实标注 ScreenCaptureKit 例外。
- **刘海悬停面板**（A，以后，默认关）。
- 「消耗瞬态提示」「步进刷新频率」等随增量一加入。

悬停参数（150ms / 200ms）**不放进设置**（⑤，只在做 A 时适用）。

### 3.5 「实时增量」的可行性结论（「正在运行」与消耗瞬态的数据基础）

- **能做，但是步进准实时，不是逐 token 流式**：Zcode / OpenCode 在每个 step 落盘后 ≤5s 可见（默认 5s 轮询）。
- 代码已核实：`zcode-reader.cjs` 按 `model_usage.started_at` 逐行读取；`opencode-reader.cjs` 按 `step-finish` part 的 `at` 投影；`monitor.cjs` 是 `schedule(delay)` 轮询 + broadcast——增量 = 游标之后的新行求和。
- **前置条件：依赖 T7.2 实时尾随通道**。现有 `ToolSources.run()` 同一时间只允许一个 worker，新查询会取消正在进行的查询，并且每次都全量扫描，不能直接用于 2–5 秒的刷新。T7.2 新建独立常驻的 `desktop/live-tail.cjs`，与 `ToolSources.run()` 互不取消，只在面板打开或「正在运行」可见时运行。
- **分层承诺**：Zcode / OpenCode 步进增量；**Codex 会话增量显示「—」**（rollout metadata 非请求数，既定结论），用官方 5h/周百分比下降作活跃信号；Claude 首版不显示实时。
- **规则**：「运行中」= 最近 step 记录在 ~90s 内、来自会话本体（排除 legacy mirror / fork 继承）；不用进程存在推断，不推断账户归属（accountId null 不变）；cache/reasoning 不重复计；失败/取消的 reported usage 仍计入；UI 三态不显示 0。
- **消耗瞬态措辞**：本地 turn 增量优先；轮询差值（如 Codex）只显示「余量 −0.8%」，**不做「本轮」归因**（平台轮询有滞后且聚合不透明）。
- 2s 高频轮询的 CPU/内存在真机验收时给实测数，不凭推断宣称。

## 6. 实施约束（来自项目 AGENTS.md，实现阶段必须遵守）

- 交付按当前 [AGENTS.md](../../AGENTS.md) 第 7 节与 [RELEASING.md](../RELEASING.md)：四种安装包由 CI 的 Release 工作流产出，验证包内版本与源码一致，保留旧发布产物；不得把仅源码变更报告为已交付。
- **Windows 行为零改动**（托盘点击仍打开主窗口）；appId / executableName / userData 路径不变；不引入新原生依赖。
- 菜单栏图标沿用已批准的刻度环 Logo（母版 `desktop/assets/brand-mark.svg`），只改变刻度的点亮状态，不重画 Logo；品牌或图标改动按 AGENTS 第 8 节验证渲染结果。
- 升级不改现有用户偏好与窗口位置；经典悬浮窗行为不变。新设置项的默认值在升级时按 RELEASING 的升级 profile 规则处理。
- 刘海悬停面板（A）只在内建刘海屏启用；外接屏和 Windows 不提供。
- Mac 当前交付形态：arm64 DMG/ZIP（ad-hoc 签名、hardened runtime、无公证，D4）；真机验收仍待用户按 Mac 验收清单完成。
- 数据红线：缺失显示「—」非 0；工具记录 accountId null；不读取任何对话内容/凭据；Codex 查询只读；不做长时间稳定性测试。
- 版本号：按 1.9.0 线规划（D3）；当前版本见 [AGENTS.md](../../AGENTS.md)。
