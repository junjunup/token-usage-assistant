# Token 用量助手 1.7.0：账户关联与数据核对

2026-09-24 · Windows x64 · 对应原计划阶段 4。保留 1.6.0 DeepSeek 官方余额、所有套餐连接、工具采集及悬浮窗行为。阶段 5 macOS、阶段 6 第三方评估尚未开始。

## 使用入口

1. 打开“账户与设置”，在平台连接和工具数据源下面找到“计费账户与工具关联”。
2. 创建计费账户组：填写名称，选择属于同一真实计费账户的一个或多个连接，指定一个主查询连接，并确认成员属于同一账户。不同平台、地区、组织范围或已知身份冲突不能归组。同一个连接不能放入两个组。
3. 添加工具关联：指定数据源、计费账户组、生效时间、可选结束时间及供应商 / 模型条件，再确认归属。供应商和模型标识精确匹配，可从工具分析的模型排行查看；留空代表全部。开始时间包含、结束时间不包含；相交条件和重叠时段会被拒绝。
4. “用量分析 → 工具分析 → 工具计费账户”支持全部记录、未关联 / 待确认记录、指定账户。模型、项目、会话筛选继续生效。只有明确选择了具有有效账期的账户组，才开放本账期。
5. 左侧新入口“账户核对”展示主查询连接的平台数据、明确关联的工具统计、规则依据、观察到的时间范围及无法比较的原因。

新增规则默认从打开 / 重置表单的当前时刻起生效；关联历史数据时需明确调整时间。删除组同时删除其规则；删除规则不删除任何工具记录、账户连接或凭据。跨时间换 Key / 账户时，请先设置旧规则的结束时间，再建立新规则。

## 计数与归属规则

- 平台连接是查询凭据；计费账户组是人工确认的归属。多个 Key 可能属于同一真实账户，但应用不据此自动猜测。
- 组内只采用一个主查询连接的平台快照。多个 Key 的余额或共享额度不相加，平台汇总也不与工具记录相加。连接轮询与提醒仍分别运行。
- 工具原始文件和既有索引不写入计费账户。关联在查询时根据已确认规则计算，切换总览账户不会更改记录归属。默认不关联；未匹配、冲突和失效记录保持未关联。
- 重命名组、重命名来源和仅切换主查询连接保留规则。更换密钥、增删组成员或发现已知平台身份变化后，需重新确认归组并编辑保存关联。删除连接会使其组失效。
- 来源绑定物理文件身份。仅移动同一文件且更新位置可保留规则；替换为新文件、不同安装或文件身份改变需要重新确认。查询期间配置变化会取消结果，避免过期结果误归属。
- 生效范围由用户确认，并不能证明账户完整覆盖。供应商 / 模型条件本身也不能自动推断使用了哪个 Key。
- 用量仍采用“已报告用量”，失败 / 取消时明确返回的 Token 仍计入；缓存、推理子项不重复相加；缺失字段保持未知；币种不默认兑换。

## 为什么可能显示“无法核对”

核对必须同时具备：同一账户范围、严格一致的开始和结束时间、相同单位及统计口径、双方明确完整覆盖、有效且及时的数值。任一条件缺失时，差值和误差率保持“—”。平台为零时也不能除以零计算误差率。

| 现有平台数据 | 本版核对能力 |
| --- | --- |
| DeepSeek 官方余额 | 显示币种和余额作为参考；余额受充值、赠金影响，不能与 Token 或工具估算费用核对 |
| ChatGPT / Codex、Claude、GLM、MiniMax、火山套餐额度 | 额度窗口和百分比不能直接换算为 Token 或实际账单，显示原因 |
| Command Code 汇总 | 显示平台返回的 Token / 费用与时间依据；当前接口未确认严格结束时间和与本机相同的请求口径，不能输出误差率 |
| 所有本机工具来源 | 只证明观察到了这些记录；不能证明覆盖同账户在其他设备、Key 或工具上的全部用量 |

因此，1.7.0 当前支持的平台 / 采集器组合均不能声称已完成自动真实核账。已交付人工关联、范围筛选、单一主查询来源和核对依据界面；没有用样例补齐上述事实缺口。工具费用始终是单价估算，平台余额或汇总也不冒充完整账单。

## 升级与隐私

保留 Windows 应用 ID、凭据加密方式、账户配置、偏好、窗口位置、模型单价及工具来源。新增 `account-links.json` 保存组、规则、内部身份摘要和人工确认范围，不保存密钥或对话正文；文件损坏时保留原文件，暂停关联，不静默覆盖。内部身份摘要不传给界面。

升级不会自动创建组或关联。旧版本忽略新增关联文件，原设置仍可读取。请从安装版或免安装版中选择一种使用；新包不会自动替换目前已启动的旧程序。旧版本发布文件保留。
