# Mac 真机验收清单

> 适用：Apple Silicon、macOS 13+，本机构建的 ad-hoc 签名、未公证的 `Token 用量助手.app`（见 [MAC-APP-1.8.0-beta.5](MAC-APP-1.8.0-beta.5.md) 与 [RELEASING](RELEASING.md)）。
> 由**用户在真机上**逐项执行并填写「实测记录」。执行模型不得替用户把任何一项标为通过（证据等级 ③ 只能来自真机）。
> 每次发版（尤其是覆盖升级、签名变化时）都要重新执行第 3 项；因为 D4 决定继续使用 ad-hoc 签名，每次构建的签名都不同。

**填写方式**：在「实测记录」中写日期、被测包的文件名（例如 `TokenUsageAssistant-Mac-arm64-1.8.0-beta.6.dmg`）、结果（通过 / 不通过 / 未测）和简短说明；如有截图，写上文件名即可。

## 1. 从 DMG 安装，首次打开

- **步骤**：打开 DMG，把「Token 用量助手」拖入「应用程序」；在「应用程序」中**右键 → 打开 → 打开**。
- **预期**：出现「无法验证开发者」提示，确认后应用启动，出现主窗口和菜单栏图标；不会出现「已损坏，无法打开」。同一版本再次打开不再提示。
- **实测记录**：

## 2. 首次保存账户时的 Keychain 提示

- **步骤**：在全新安装（或从未保存过账户）的情况下，在「账户与设置」中连接一个账户（可用你实际拥有的 Codex 或 Command Code）。
- **预期**：可能出现钥匙串授权提示，条目名为 `TokenUsageAssistant Safe Storage`；选择「始终允许」后账户保存成功。之后重启应用，账户仍在，不再提示。
- **实测记录**：

## 3. 覆盖升级后的 Keychain 授权（每次发版必测）

- **步骤**：
  1. 在已保存账户的旧版本上，安装新构建的 DMG 覆盖（拖入「应用程序」并替换），再打开。
  2. 如果弹出钥匙串授权提示，**第一轮选「拒绝」**：观察应用的表现。
  3. 在应用的错误提示处点「重新读取」（T3.4 新增，按钮界面需按 D10 确认后才会出现在包里；如果当前包里还没有按钮，记为「未测」），这次选「始终允许」。
  4. 再次退出并重开应用。
- **预期**：
  - 第 2 步：账户列表显示「本机账户列表暂不可用，已有加密文件未被覆盖」，**已保存的账户没有丢失**。
  - 第 3 步：不重启应用就能恢复账户列表和当前选中的账户。
  - 第 4 步：不再弹出授权提示，账户都在。
- **实测记录**：

## 4. 开发版与打包版的数据隔离（T3.1）

- **步骤**：在已安装打包版并保存过账户的电脑上，在源码目录运行 `pnpm run desktop`，然后退出。
- **预期**：开发版显示为空的新环境（没有打包版的账户），数据写入 `~/Library/Application Support/TokenUsageAssistant-Dev`；打包版的 `~/Library/Application Support/TokenUsageAssistant` 下没有文件被修改；钥匙串中开发版使用独立条目 `TokenUsageAssistant-Dev Safe Storage`。打开打包版，账户仍然完好、不额外弹出授权。
- **实测记录**：

## 5. 菜单栏托盘与悬浮窗

- **步骤**：在总览中开启悬浮窗；切换到其他桌面空间；打开一个全屏应用；**右键**点击菜单栏图标；点击悬浮窗展开和收起。
- **预期**：菜单栏图标正常显示，右键菜单可用（左键弹出用量面板，见第 12 项）；悬浮窗在所有桌面空间可见，并位于全屏应用之上；展开后收起能回到原来的底边位置；关闭主窗口后应用继续驻留菜单栏。
- **实测记录**：

## 6. 睡眠唤醒与登录项

- **步骤**：让 Mac 睡眠至少 10 分钟后唤醒；在设置中开启「开机启动」，注销或重启后重新登录。
- **预期**：唤醒后数据自动刷新（不用手动点刷新）；登录后应用自动启动并驻留菜单栏。
- **实测记录**：

## 7. 真实连接 Codex；Zcode / OpenCode 来源同步

- **步骤**：连接本机 Codex（ChatGPT Pro 登录）；在「工具数据源」中添加 Zcode 和/或 OpenCode 来源并同步；在「用量分析 → 工具分析」中查看。
- **预期**：Codex 额度窗口正常显示，且只做只读查询（不发起模型调用）；工具来源同步成功，统计数字与本机工具中看到的大致吻合；不会把工具用量计入当前选中的账户。
- **实测记录**：

## 8. 通知权限

- **步骤**：首次触发额度提醒或在设置中点「测试通知」。
- **预期**：系统请求通知权限；允许后能收到通知，拒绝后应用其他功能不受影响。
- **实测记录**：

## 9. 空闲时的资源占用

- **步骤**：应用打开主窗口和悬浮窗后空闲 10 分钟，在「活动监视器」中记录「Token 用量助手」相关进程的 CPU 与内存。
- **预期**：空闲时 CPU 接近 0%（轮询时会有短暂升高），内存稳定不持续增长。只记录读数，不做长时间稳定性测试。

- **预期**：两个窗口都恢复到上次的位置和大小。
- **实测记录**：

## 11. 诊断日志（T3.2）

- **步骤**：使用一段时间后，打开 `~/Library/Application Support/TokenUsageAssistant/logs/app.log`。
- **预期**：文件存在，每行是一条 JSON；只出现模块名、错误分类、状态码、耗时等字段；**搜索不到**你的 API Key、账户名称、对话内容或完整文件路径。

## 12. 菜单栏动态图标与弹出面板（1.9.0-beta.1，T7.5–T7.7）

- **步骤**：连接至少一个有额度窗口的账户（如 Command Code、Codex 或 GLM），等待同步完成后观察菜单栏图标；左键点击图标；在面板里点其他账户；按 Esc；再左键打开后点面板外；再打开后点「主窗口 ›」。
- **预期**：图标是刻度环 Logo 加一个数值（默认 ②），数值与主窗口中剩余最少的窗口一致；面板出现在图标正下方，宽度与草图一致，默认显示图标对应的账户；点其他账户只切换面板内容，主窗口当前账户不变；Esc、点面板外、再点图标都会收起；「主窗口 ›」打开主窗口并收起面板。没有连接账户时图标为原来的静态 Logo。
- **实测记录**：

## 13. 菜单栏图标在浅色 / 深色菜单栏与告警时的颜色

- **步骤**：在「系统设置 → 外观」切换浅色与深色；如有额度低于提醒阈值（设置里 10 / 20 / 30%）或已用尽的账户，观察图标颜色。
- **预期**：正常状态下图标为单色，并随菜单栏明暗自动变白或变黑；低于提醒阈值时刻度环与数值为琥珀色，用尽时为红色；切换外观后图标几秒内跟着变化。缺数据显示「—」，窗口未启用显示「未启用」，不显示 0。
- **实测记录**：

## 14. 刘海旁空间不足时的隐藏与提示

- **步骤**：在菜单栏图标较多时（或改用 ③ 两行小字）观察本应用图标是否还在；如果看不到，打开主窗口总览和「账户与设置 → 偏好 → 菜单栏图标与面板」。
- **预期**：系统可能把图标藏到刘海后面且不提示；此时总览和设置里都出现琥珀色提示「菜单栏空间不足……可改用「① 只有刻度环」……」，形态**不会**自动改变；改用 ① 或减少其他菜单栏图标后，提示消失。
- **实测记录**：

## 15. 菜单栏设置项

- **步骤**：在「菜单栏图标与面板」里依次切换图标形态（① / ② / ③）、关闭再打开「菜单栏显示用量」、关闭再打开「告警时变色」。
- **预期**：形态立即改变；关闭「显示用量」后图标变回静态 Logo（形态和变色两项变灰），打开后恢复；关闭「告警时变色」后告警状态也保持单色。退出重开后设置保留。
- **实测记录**：

## 16. 屏幕共享、截图与锁屏时的可见性

- **步骤**：打开弹出面板，分别用系统截图（⌘⇧3 / ⌘⇧5）、屏幕录制和一款会议软件的屏幕共享拍摄；再关闭「面板截屏与共享保护」后重复一次；最后锁屏、快速切换用户，观察菜单栏。
- **预期**：开启保护时，截图 / 录屏 / 共享中通常看不到面板（部分使用新版系统接口的软件可能例外，如实记录）；关闭保护后能看到。菜单栏图标本身始终可见（不受保护覆盖，可用「菜单栏显示用量」关闭）。锁屏时的表现如实记录。
- **实测记录**：

## 17. 外接屏、多桌面空间与全屏应用中的面板

- **步骤**：接外接屏（如有）后从各屏幕的菜单栏点图标；在多个桌面空间之间切换后点图标；在全屏应用中把鼠标移到屏幕顶部露出菜单栏后点图标。
- **预期**：面板出现在被点击的图标下方，不越出屏幕；在全屏应用之上也能显示；收起后不残留。
