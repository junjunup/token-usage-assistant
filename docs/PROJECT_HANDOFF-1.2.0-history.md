## 2. 用户意图、偏好与历史决策

### 2.1 用户希望的产品

做一个直观、美观、能常驻桌面的 Token 用量助手。用户先要求设计和交互原型，参考 Command Code 网页：

https://commandcode.ai/junjunup/settings/usage

看到原型后，用户明确回复“不错，按这个标准开始开发”。后续增加的数据功能和修复必须延续该风格，而不是重新设计成完全不同的产品。

### 2.2 已确认的视觉与交互

- 中文为主；当前目标 Windows 桌面。
- 白色表面、细灰分隔线、Geist / Geist Mono 字体。
- 绿色分段额度条，紫色 Token 强调色，支持深色主题。
- 额度、Token、实际费用和估算费用在语义上分开。
- 左侧功能栏与标题栏固定，仅右侧主内容滚动；切换页面回到顶部。
- 下拉选择必须与应用主题一致，支持键盘操作，不使用展开后突兀的原生蓝色菜单。
- 左侧第二个四宫格按钮进入“用量分析”；不能再只是打开悬浮窗。首页保留悬浮窗开关。
- 月度余额应与短周期额度一起被看到，月度资金耗尽时不能因为 5 小时 / 周窗口有剩余就显示“额度充足”。
- 悬浮窗布局：用户明确选择 **“紧凑常驻＋点击展开更多数据”**。
- 升级时保留已有凭据、偏好、窗口位置。

历史中曾出现用户答复“1B 2C 3C，按你推荐的就行”，但原始三个问题在当前交接材料中不完整；不得凭这串编号推断新的产品要求。以上明确决策及现有界面是可依赖的依据。

### 2.3 最近两次需求

1. 用户计划未来开源，询问目前是否绑定 Zcode / Command Code、更换 Coding Plan 与 Agent 是否兼容、如何尽可能通用，要求先讨论不编码。
2. 用户要求把上下文、已完成内容、准备推进部分写成 skill 或 Markdown，以便在另一台电脑继续开发、使用和对话。

本次选用项目内 Markdown，避免依赖某一台电脑的技能安装目录；配套更新 `AGENTS.md` 的交接入口。

## 3. 已完成的产品能力

### 3.1 原生桌面基础

- Electron 主窗口 + 独立悬浮窗 + Windows 系统托盘。
- 关闭主面板后驻留托盘；托盘右键退出才结束程序。
- 单实例运行、窗口位置和外观设置持久化、窗口状态同步。
- 悬浮窗置顶、固定 / 解除固定、拖动、进入详情。
- 轮询默认 60 秒，可选 30 / 60 / 120 / 300 秒。
- 提醒阈值可选 10% / 20% / 30%；通知去重，额度恢复后允许再次提醒。
- 开机启动默认关闭；启用后静默驻留托盘。实现已存在，但未通过系统重启完成验收。
- 断网及部分接口失败保留上次成功数据，标记过期 / 错误和更新时间。
- 429 遵循 Retry-After，手动刷新不绕过冷却；网络退避，认证失败停止自动重试；休眠恢复后刷新。
- API Key 仅通过本机应用配置，Electron `safeStorage` / Windows DPAPI 加密存储。

### 3.2 用户批准的八项用量分析

| 功能 | 当前实现与边界 |
|---|---|
| 时间范围 | 今日、近 7 天、本账期；账期起点依赖已连接账户提供的订阅信息 |
| 用量趋势 | 今日按小时，长范围按天；Token / 费用 / 请求数切换，可展开精确数表 |
| 模型排行 | Token / 请求数 / 估算费用排序，可按模型筛选、按供应商分别设置单价 |
| 项目与会话 | 按项目目录聚合，点击下钻会话，再联动趋势和缓存；不读取会话正文 |
| 缓存分析 | 普通输入、缓存读取 / 写入、读取命中率、估算节省和字段覆盖率 |
| 请求健康 | 完成 / 失败 / 取消 / 其他状态，平均 Token 和费用；首页有健康摘要 |
| 额度来源 | 月度套餐、购买、免费余额和可取得的来源消耗；未知字段保持未知 |
| 消耗速度 / 预测 | Token / 分钟、费用 / 小时；满足样本条件时预测 5 小时 / 周窗口触顶 |

### 3.3 1.2.0 对用户五项反馈的处理

1. **左侧栏跟随页面下滑**：固定侧栏和标题栏，只滚动内容区。
2. **选择框与主题不一致**：统一自定义下拉菜单；方向键 / Enter / Esc / 输入定位；长模型名与路径换行，必要时改变弹出方向。
3. **缺少月剩余额度**：首页顶部和悬浮窗补充月余额；综合健康、低余额提醒和耗尽提醒纳入月度资金。购买 / 免费余额单独呈现，不把月额度耗尽等同于所有资金都不可用。
4. **悬浮窗信息不足**：默认紧凑，点击展开本账期 Token、费用、请求数、成功率、购买 / 免费余额与同步时间；可手动刷新；展开状态保存在本机。
5. **5 小时刷新时间不显示**：区分未启动窗口、缺失时间、有效倒计时与已过期等待同步，不凭打开应用时间生成倒计时。

1.2 验证时的真实归一化快照为：5 小时 `used=0`、`resetState=idle`，周窗口 `scheduled`。这是当时的快照，表示 5 小时窗口尚未启动，不是“倒计时遗漏”；不应把这个历史状态写死在新环境。

悬浮窗设计尺寸：紧凑约 `324 × 366`，展开约 `324 × 552`；Windows 缩放可能造成少量外框像素差异。

## 4. 数据口径：继续开发时必须保留

### 4.1 账户来源

- 来自 Command Code 账户 / 组织汇总，不是某台电脑或 Zcode 独占的用量。
- 接口费用按实际返回值显示；不把账户账单换算成精确剩余 Token。
- 账户分时图来自助手采集的汇总差值；启动前、离线、缺样区间不能补零或伪造逐请求历史。
- 账户接口目前没有提供供本项目使用的模型 / 项目 / 会话 / 缓存细分；相应功能依赖本机来源。
- 账期未确认时显示累计口径，不冒充本月或本账期。
- 月额度总额与百分比，仅在同次同步、同一账期的有效月余额与消耗可配对时推导；不能从套餐名称猜额度。

### 4.2 本机 Zcode 来源

- 默认只读 `%USERPROFILE%\.zcode\cli\db\db.sqlite`；支持 `ZCODE_HOME` 和手动选文件。
- 读取 `model_usage` 的明确字段及 `session.directory`，不使用 `SELECT *`。
- 必需用量字段：`id`、`session_id`、`started_at`、`model_id`、`status`、`input_tokens`、`output_tokens`；会话表需 `id`、`directory`。
- 可选字段：`provider_id`、`cache_creation_input_tokens`、`cache_read_input_tokens`、`computed_total_tokens`。
- 不读取提示词、回答、会话标题、错误正文、原始响应或客户端凭据。
- 只汇总完成请求的 Token / 费用；成功率为完成 /（完成＋失败），取消和进行中单列。
- 账户成功率与平均值按接口总请求数口径计算，不能与本机口径无说明地互换。
- 现有 Zcode 输入数包含缓存输入，拆分时避免重复累计；这是该适配器语义，不能强加给其他客户端。
- 本机费用按手动单价估算，单位 USD / 百万 Token。未配置价格表示未知；用户明确输入 0 才是该类免费。
- 缓存读取的估算节省不包含缓存写入溢价。
- 单次读取最多 100,000 条，达到上限提示缩小范围。

### 4.3 历史与预测

- 账户与本机记录不能相加；两侧可能覆盖同一批调用，也可能覆盖不同设备。
- 当前账户历史每分钟最多一个样本，最多保留 31 天且不超过 16,000 个样本；默认连续每分钟采样实际约 11 天触及数量上限。
- 预测至少需要 10 分钟连续、新鲜样本；离线、过期、账期变化、窗口重置时按规则降级。
- 预测仅表示“近期速度不变”的条件推演，不是最终账单承诺。
- 未知数据保留为未知，不能变成 0、100% 或“额度充足”。

### 固定的 Command Code 接口

目前仅向 `https://api.commandcode.ai` 发起 GET：

- `/alpha/whoami`
- `/alpha/billing/credits`
- `/alpha/billing/subscriptions`
- `/alpha/usage/summary`（账期确认后带 `since`）

Bearer Key；可配置组织 ID；固定域名，不跟随重定向；不会调用模型生成接口。这些 `/alpha` 接口不是已公开承诺稳定的通用计费契约。

- 浏览器不能配置真实 Key；不能把浏览器截图中的数字当作真实账户用量。
- `analytics-preview-v1.1.jpg`、`widget-expanded-v1.2.jpg` 为示例数据截图。

## 6. 换电脑：带什么、怎么继续使用

### 6.1 配套交付物

1. **源码迁移包**：`TokenUsageAssistant-Source-Handoff-1.2.0.zip`。解压得到 `commandcode-companion/`，包含本文、项目指引、锁文件、源码、测试、资源、示例截图和历史参考材料。
2. **可选免安装程序**：`TokenUsageAssistant-Portable-1.2.0.exe`。用于新电脑直接运行，无需 Node.js。
3. **可选安装程序**：`TokenUsageAssistant-Setup-1.2.0.exe`。与免安装版任选其一。

源码迁移包不包含 `node_modules/`、`dist/`、旧 release 目录、任何用户数据或 Windows 凭据。它也不包含 EXE；需要即开即用时，另行携带免安装程序。没有依赖旧电脑的聊天链接或本机绝对源码路径。

### 6.2 新电脑使用

1. 使用 Windows x64。当前仅 Windows 11 x64 完成验证，不把其他系统视作已支持。
2. 双击免安装程序，或自行运行安装包。当前版本未代码签名；这是现有交付属性。
3. 在应用“账户与设置”重新输入自己的 Command Code API Key；个人账户组织 ID 留空，有组织需求再填写。
4. 选择新电脑上实际的 Zcode 数据库。旧电脑的用户名、绝对路径不能照搬。
5. 核对账户数据与官方网页；确认月余额、窗口状态、账期及组织范围。
6. 开启需要的悬浮窗、通知和主题。拖动悬浮窗前先解除固定。

新电脑没有 Zcode 记录时，本机分析应显示空状态 / 缺少数据，而不是恢复出旧电脑的历史。若用户需要合并或导入旧设备记录，这是**尚未实现的独立需求**。

### 6.3 私有数据与迁移边界

当前用户数据目录通常为 `%APPDATA%\commandcode-companion`，实际由 Electron `app.getPath('userData')` 决定。免安装版也使用该目录，而不是 EXE 旁边。

| 文件 | 含义 | 新电脑处理 |
|---|---|---|
| `credentials.encrypted.json` | Windows DPAPI 加密的 Key / 组织 | **不作为跨电脑凭据备份**，在新电脑应用内重新输入 |
| `settings.json` | 外观、提醒、窗口位置等 | 默认重新设置；需要迁移时先确认路径和屏幕差异，不自动覆盖 |
| `snapshot.json` / `history.json` | 账户快照 / 采样历史 | 私有运行数据，不进源码包；当前没有用户可用的导入合并流程 |
| `local-pricing.json` | 用户设置的估算单价 | 可在用户明确需要时单独迁移，需核对供应商 / 模型标识 |
| `local-source.json` | 本机数据库绝对路径 | 在新电脑重新选择 |

不要把 Key 发到聊天、Markdown、Git 仓库或日志，也不要为了迁移而解密 / 导出旧凭据。源码和对话上下文的迁移不等于账户认证迁移。

原电脑位置仅供寻找文件，**不是新电脑的配置值**：

```text
C:\Users\张董\Documents\Codex\2026-09-23\token-x20\outputs\commandcode-companion
```

新电脑可放在任意用户选择的路径，例如 `D:\Projects\commandcode-companion`。

## 7. 换电脑：开发环境、命令与验收

## 8. 多平台兼容性：已经讨论清楚的结论

### 8.1 当前是否绑定

当前不是要求用户必须同时使用两者，而是两条读取器分别绑定：

| 组合 | 当前结果 |
|---|---|
| Zcode + Command Code | 当前完整目标组合 |
| Zcode + 其他供应商 | Zcode 按兼容格式记录时，本机统计通常可用；其他供应商账户余额尚不支持 |
| 其他客户端 + Command Code | 账户额度查询可用；其他客户端本地明细尚不支持 |
| 其他客户端 + 其他供应商 | 两侧都需要新增适配器 |

`desktop/api.cjs` 固定 Command Code 域名；`zcode-reader.cjs` 固定 Zcode 表结构。仅换 Key / Base URL 或手动选择另一个数据库文件，不会自动完成适配。

### 8.2 可行性与边界

- 可改为多平台架构，保留窗口、托盘、悬浮窗、筛选、图表与大部分统计逻辑。
- 应将“供应商账户额度适配”和“客户端本地记录适配”分开，避免为每一种组合写整套实现。
- OpenAI / Anthropic 模型调用协议兼容，不等于账单查询接口兼容。
- 套餐可能按 Token、请求、积分、货币或百分比计量；周期也可能不同。
- 按月付费不等于供应商一定暴露“月总额度”；不能将 Command Code 的 5 小时 / 周 / 月规则套给所有平台。
- CLI、本机桌面、远端 / 云端会话的数据覆盖范围可能不同，必须分别验证。
- 用户期望的“完美适配”不能作为全平台全字段保证。可实现的目标是：有可靠数据的功能完整支持；缺失时明确说明，其他功能独立继续运行。
- 多平台不等于跨操作系统；首轮仍可保持 Windows 范围。

## 9. 准备推进的方案：建议，尚未批准实施

### 9.1 建议架构

1. **供应商适配器**：认证、账户范围、套餐 / 账期、余额、额度窗口、重置时间、实际账单；原 Command Code 作为首个适配器保留。
2. **客户端适配器**：只读本地记录或官方监测接口，提取时间、模型、项目、会话、Token 分类和请求状态；原 Zcode 作为首个适配器保留。
3. **统一统计层**：规范数据单位、输入 / 缓存包含关系、时区、来源标识、去重和价格估算。
4. **按能力展示的界面**：根据来源支持什么显示什么，额度窗口不再写死只有三种；保留当前视觉语言。

建议数据约束：

- 额度以窗口列表表示，记录名称、周期、单位、已用 / 剩余 / 上限、重置状态、作用范围。
- 每项指标记录来源、更新时间、可用状态及“官方返回 / 推导 / 估算”属性。
- 账户、供应商、客户端实例分开标识，隔离凭据、缓存、历史、通知和错误。
- 不同货币、请求与 Token 不能直接相加；不同账户剩余百分比不能简单求和。
- 官方扣费与本机估算分开；同一次调用不能因两个来源都出现而重复计入。
- 供应商与本机模型别名的对应关系不能靠模型名猜测；需要可靠标识或用户配置。
- 优先官方查询 / 本地日志 / 明确启用的监测机制；首版不强制代理模型请求，不修改 Agent 的正常调用链。
- 先实现内置适配器接口，之后再考虑社区扩展方式，不需要一开始加载任意第三方脚本。
